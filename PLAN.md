# FuelMuhafiz — Excel → Multi-Tenant Web Application

## Context

`system-requirements.xlsx` is a working offline petrol-pump management workbook (11 sheets, generated by openpyxl, edited on Excel Android). It runs a single station with 1 pump / 2 tanks and is the customer's current production system. Its own Instructions sheet states the intent: _"When you are ready for a proper multi-user offline desktop or web software … we will build it on top of this same structure."_

This repo is a fresh Laravel 13 + Inertia v3 + React 19 + `stancl/tenancy` v3 starter kit with only auth scaffolding — no domain code yet. The task is to turn the workbook into a multi-tenant, multi-station web application.

Two problems in the workbook drive the whole design:

1. **Triple data entry.** The same day's activity is typed into `Sales`, `Meter Readings`, and `Tank Stock` separately, then reconciled by hand. The sample data proves this fails: `Meter Readings` has closing 126,018.18 on day 46238 followed by opening 125,294 on 46239 (a meter went _backwards_), and `Tank Stock` opening stock climbs 12,000 → 12,100 → 12,200 while book closing says 18,644 → 10,894 → 10,775. The three records silently disagree, so variance figures — the entire point of the exercise — are meaningless.
2. **Stored aggregates that drift.** `Credit Customers!E` (Outstanding) is a hand-typed number the sheet itself admits is "updated manually"; `Settings!D17:D18` (Current Stock) must be retyped after every dip.

**Outcome:** nozzle meter readings become the single source of truth. Litres sold, sale value, tank stock, and customer balances are all _derived_, so they cannot disagree. Every figure is attributable to a user via an audit log.

## Decisions (confirmed with the user)

| Decision          | Choice                                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| Tenant boundary   | Tenant = **company**; owns many stations inside its own database                                          |
| Data model        | **Derive** everything from nozzle meter readings                                                          |
| Users             | Live **inside each tenant DB** (central DB keeps platform super-admins only)                              |
| Region            | **Pakistan** — PKR, NTN/STRN, Asia/Karachi                                                                |
| Database          | **MySQL/MariaDB** for prod, SQLite `:memory:` for tests                                                   |
| Tenant URL        | **Subdomain** — `acme.fuelmuhafiz.com`                                                                    |
| Milestone 1       | Foundation + daily operations (credit ledger & reports follow)                                            |
| Also designed for | Staff/shift cash reconciliation, supplier payables, printable day-close report, audit log + price history |

## Workbook → application mapping

| Sheet                  | Becomes                                | Notes                                                                                                           |
| ---------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Instructions           | —                                      | Replaced by onboarding wizard                                                                                   |
| Settings (pump info)   | `stations`                             | Pump name/address/owner/contact; **GSTIN → NTN + STRN**                                                         |
| Settings (fuel prices) | `fuel_types` + `fuel_prices`           | `B12:C13` (price + last-updated) becomes an append-only price history with `effective_from`                     |
| Settings (tanks)       | `tanks`                                | `C17` capacity kept; `D17` "Current Stock" **dropped** — derived from `stock_movements`                         |
| Settings (pump/nozzle) | `pumps` + `nozzles`                    | `Pump 1 - Nozzle 1 → Petrol (Tank 1)` becomes `nozzles.tank_id`; fuel type derives via tank                     |
| Settings (user roles)  | `UserRole` enum + policies             | Admin / Manager / Operator, as documented in `A28:A30`                                                          |
| Meter Readings         | `shifts` + `nozzle_readings`           | **Source of truth.** `F = E - D` becomes `litres_sold = closing - opening - test_litres`                        |
| Sales                  | `shift_payments` + credit transactions | Per-transaction rows **eliminated**; only the payment-mode split is entered                                     |
| Fuel Receipts          | `fuel_deliveries` + `suppliers`        | Restores the deleted `F`/`G` columns (Rate, Total Amount) as real fields, feeding payables                      |
| Tank Stock             | `stock_movements` + `tank_dips`        | `G = D+E-F` and `I = G-H` become **queries**, not typed cells                                                   |
| Expenses               | `expenses` + `expense_categories`      | Dropdown list `Salary,Generator Fuel,Maintenance,Electricity,Stationery,Other` seeded                           |
| Credit Customers       | `credit_customers`                     | Outstanding becomes a derived sum, not a column                                                                 |
| Credit Transactions    | `credit_transactions`                  | `Credit Sale` / `Payment Received` → enum                                                                       |
| Dashboard              | Dashboard controller + queries         | Keeps the `<20% LOW STOCK / <40% Reorder Soon / OK` thresholds from `Dashboard!F16`, made per-tank configurable |
| Reports                | Reports module                         | Gains **real** gross profit (sales − COGS from delivery cost), vs the workbook's sales − expenses               |

Dropdown values recovered from the workbook's data validations and preserved as enums/seeds: pumps `Pump 1,Pump 2`; fuels `Petrol,Diesel` (extend for PK: Hi-Octane/HOBC, HSD, LDO, CNG, LPG); payment `Cash,UPI,Card,Credit` (localise: Cash, Card, Wallet, Bank Transfer, Credit); tanks `Tank 1,Tank 2`.

> **Note on the `Sales` sheet:** it is empty in the file — the user cleared it (only styling and dropdowns survive). Its schema was reconstructed from `Dashboard!B7:B10` and `Reports!B5:B9` formulas: `A`=Date, `C`=Pump, `D`=Fuel, `E`=Litres, `F`=Payment mode, `G`=Amount, `H`≈Customer/Vehicle. Column `B` (narrow) is unidentifiable — likely Time or Bill No. This does not block anything, because per-transaction sales are replaced by derivation. Similarly `Fuel Receipts!F4:G7` was deleted (the saved selection is literally `F4:G7`) — Rate and Amount are being restored deliberately.

## Phase 0 — Tenancy & auth foundation

This must land before any domain code. Four pieces of existing wiring need changing.

### 1. Move auth into the tenant database

Copy into `database/migrations/tenant/` (keeping the central copies for platform super-admins — same table names, different databases; `DatabaseTenancyBootstrapper` swaps the default connection):

- `users` + `password_reset_tokens` (mirroring `database/migrations/0001_01_01_000000_create_users_table.php`, `uuid` PK)
- two-factor columns (from `2025_08_14_170933_add_two_factor_columns_to_users_table.php`) — fold directly into the tenant `users` migration
- `passkeys` (from `2024_01_01_000000_create_passkeys_table.php`)

`sessions`, `cache`, `jobs` already exist under `database/migrations/tenant/`. `App\Models\User` needs **no change** — it resolves against whichever connection is active.

### 2. Switch to subdomain identification with universal auth routes

`InitializeTenancyByDomain` → `InitializeTenancyBySubdomain` in `routes/tenant.php`.

Fortify registers its routes from its own service provider with `'domain' => config('fortify.domain', null)`, so `/login` currently resolves on tenant subdomains **without** tenancy initialised — it would authenticate against the central database. Fix using tenancy's built-in mechanism (verified present at `vendor/stancl/tenancy/src/Features/UniversalRoutes.php`):

- Enable `Stancl\Tenancy\Features\UniversalRoutes::class` in `config/tenancy.php` `features`
- Register an empty `universal` group in `bootstrap/app.php` via `$middleware->group('universal', [])` (`Middleware::group()` confirmed at `vendor/laravel/framework/src/Illuminate/Foundation/Configuration/Middleware.php:245`)
- Set `config/fortify.php` `'middleware' => ['web', 'universal', InitializeTenancyBySubdomain::class]`

`UniversalRoutes` sets `$onFail` on the identification middleware so that on the central domain it continues in central context (super-admin login) and on a subdomain it initialises the tenant (staff login). `PreventAccessFromCentralDomains` must **not** be applied to Fortify routes.

Also enable `Stancl\Tenancy\Features\UserImpersonation::class` so onboarding can hand a freshly-created owner straight into their subdomain.

### 3. Fix the central-domain URL default

`app/Providers/AppServiceProvider.php:configureCentralDomain()` falls back to `$centralDomains[0]`, which is `127.0.0.1` (first entry of `TENANCY_CENTRAL_DOMAINS`). Any central route generated from a tenant subdomain would point at `127.0.0.1`. Fall back to the **`APP_URL` host** instead. The existing `domain('{centralDomain}')` constraint in `bootstrap/app.php` correctly keeps central routes off subdomains (Laravel anchors domain parameters, so `acme.fuelmuhafiz.test` will not match `fuelmuhafiz\.test`) — leave that as-is.

### 4. Tenant provisioning & tests

- `Tenant::getCustomColumns()` (from `stancl/virtual-column`, confirmed) declares real columns; add a central migration for `name`, `ntn`, `strn`, `contact_name`, `contact_phone`, `contact_email`, `currency` (default `PKR`), `timezone` (default `Asia/Karachi`), `is_active`, `trial_ends_at`. Everything else keeps flowing into the `data` JSON column.
- `TenancyServiceProvider` already runs `CreateDatabase` + `MigrateDatabase` synchronously on `TenantCreated` — leave it, but enable `Jobs\SeedDatabase` and add a `database/seeders/TenantDatabaseSeeder.php` that seeds fuel types, expense categories and the owner user.
- **New:** `tests/Concerns/InteractsWithTenancy.php` — creates a `Tenant` + `Domain` in `setUp`, then `tenancy()->initialize($tenant)`. `SQLiteDatabaseManager` writes tenant files to `database_path($name)` (confirmed), so add `/database/tenant*` to `.gitignore` and delete the tenant in `tearDown` (`TenantDeleted` → `DeleteDatabase` removes the file).
- **New:** `php artisan fuelmuhafiz:demo-tenant` console command that provisions a tenant reproducing the workbook's sample data (2 tanks 20,000 L petrol / 15,000 L diesel, 1 pump / 2 nozzles, Rs 102.50 & Rs 90.75, five days of shifts, the two deliveries, four expenses, four credit customers). This is the manual verification path — no throwaway scripts.
- `.env` / `.env.example`: `DB_CONNECTION=mysql`, `SESSION_DOMAIN=null` (host-only cookies keep each subdomain's session separate), `TENANCY_CENTRAL_DOMAINS` unchanged. Local dev needs a wildcard `*.fuelmuhafiz.test` (Herd supports this).

## Phase 1 — Domain schema

All in `database/migrations/tenant/`. UUID primary keys throughout, matching `users`/`domains`. Money `decimal(14,2)`, litres `decimal(12,3)`, meter readings `decimal(14,3)`, prices `decimal(10,3)` — mirroring the workbook's `0.000` number format.

**Masters:** `stations` · `station_user` (pivot — which staff see which station) · `fuel_types` · `tanks` (`capacity_litres`, `dead_stock_litres`, `reorder_percent` default 40, `critical_percent` default 20) · `pumps` · `nozzles` (`pump_id`, `tank_id`, `label`, `notes`) · `fuel_prices` (`station_id`, `fuel_type_id`, `price_per_litre`, `cost_per_litre`, `effective_from`, `created_by`) · `suppliers` · `expense_categories`

**Operations:** `shifts` (`station_id`, `business_date`, `label`, `status`, `opened_by`, `closed_by`, cached `total_litres`/`total_sales_amount`; unique on `station_id + business_date + label`) · `nozzle_readings` (`shift_id`, `nozzle_id`, `opening_reading`, `closing_reading`, `test_litres`, `litres_sold`, `unit_price`, `amount`) · `shift_attendants` · `shift_payments` (`method`, `amount`) · `fuel_deliveries` · `supplier_payments` · `tank_dips` · `stock_movements` (`tank_id`, `type`, signed `quantity_litres`, `balance_after`, polymorphic source, `occurred_at`) · `expenses`

**Cross-cutting:** `audit_logs` (`user_id`, `auditable_type`/`_id`, `event`, `old_values`, `new_values`, `ip_address`) — driven by an `App\Concerns\Auditable` trait on model events, no new package.

**Enums** in `app/Enums/`: `UserRole`, `PaymentMethod`, `ShiftStatus`, `StockMovementType`, `CreditTransactionType`, `ExpenseCategoryType`. TitleCase keys per project PHP rules.

Every model gets a factory and the seeders listed above.

### Derivation engine (`app/Actions/`)

The heart of the change. Each action is a single `DB::transaction`.

- **`CloseShift`** — validates `closing_reading >= opening_reading` and that `opening_reading` equals the same nozzle's previous closing (the check the workbook lacks); resolves the price via `FuelPriceResolver` (latest `fuel_prices` row with `effective_from <=` shift close); computes `litres_sold = closing - opening - test_litres` and `amount = litres_sold × unit_price`; writes one negative `stock_movements` row per tank; caches shift totals; sets `status = closed`.
- **`RecordFuelDelivery`** — delivery + positive `stock_movements` row + supplier payable.
- **`RecordTankDip`** — dip row, then variance = book stock − dip (the workbook's `I = G - H`).
- **`TankStockCalculator`** — book stock at time _T_ = `SUM(stock_movements.quantity_litres WHERE occurred_at <= T)`. Replaces `Settings!D17` and all of `Tank Stock` columns D–G.
- **`DashboardMetrics`** — today's sales / cash / digital / credit / expenses (replacing `Dashboard!B7:B12`), tank fill % + status, credit outstanding.

### HTTP + UI

Follow existing conventions exactly: resourceful controllers returning `Inertia::render()`, Form Requests under `app/Http/Requests/<Domain>/`, `Inertia::flash('toast', [...])` + `to_route()` (as in `app/Http/Controllers/Settings/ProfileController.php`), policies for the Admin/Manager/Operator matrix, Wayfinder actions imported from `@/actions/...`.

Domain routes go in **`routes/tenant.php`** (currently a placeholder closure), split into `routes/tenant/{operations,masters,reports}.php`, all behind `['web', InitializeTenancyBySubdomain::class, PreventAccessFromCentralDomains::class, 'auth', 'verified']`.

React pages under `resources/js/pages/`: `dashboard`, `shifts/`, `deliveries/`, `tanks/`, `expenses/`, `stations/`, `prices/`, `suppliers/`, `reports/`. Reuse `Page.layout = { breadcrumbs: [...] }` (per `resources/js/pages/dashboard.tsx`), `<Form {...Controller.action.form()}>` with `InputError` (per `resources/js/pages/settings/profile.tsx`), and the `useFlashToast` hook. Add a station switcher and new nav groups to `resources/js/components/app-sidebar.tsx` (`mainNavItems` is a plain `NavItem[]` — `NavMain` needs a grouped variant).

**Missing shadcn/ui components to add** (present today: alert, avatar, badge, breadcrumb, button, card, checkbox, collapsible, dialog, dropdown-menu, icon, input, input-otp, label, navigation-menu, select, separator, sheet, sidebar, skeleton, sonner, spinner, toggle, toggle-group, tooltip): **table, tabs, popover, calendar, alert-dialog, textarea, radio-group, switch, command, pagination**. `components.json` is `new-york` / `neutral` / Tailwind v4 CSS variables — `npx shadcn@latest add` will match.

Use `Inertia::defer()` for the heavier dashboard/report panels with pulsing `Skeleton` empty states, per the project's Inertia v3 guidelines.

## Verification

1. **Migrations** — `php artisan migrate:fresh` then `php artisan tenants:migrate`; inspect with the Boost `database-schema` tool on both the central and a tenant connection.
2. **Provision** — `php artisan fuelmuhafiz:demo-tenant`, confirming `CreateDatabase` → `MigrateDatabase` → `SeedDatabase` runs and a tenant database appears.
3. **Derivation correctness (the important one)** — feature tests asserting: closing − opening − test = litres sold; amount = litres × the price effective at close; a negative `stock_movements` row per tank; book stock matches `opening + received − sold` for the workbook's own five sample days; variance = book − dip; a backwards meter reading is _rejected_ (the bug present in the sample data); a price change mid-period does not retroactively alter closed shifts.
4. **Tenancy isolation** — tests asserting a user in tenant A cannot authenticate or read data on tenant B's subdomain; `/login` on a subdomain hits the tenant `users` table while `/login` on the central domain hits the central one; central routes 404 on subdomains.
5. **Authorization** — an Operator can submit meter readings but cannot edit prices, expenses, or close a shift; a Manager cannot manage stations.
6. **UI** — `composer run dev`, then browse `http://acme.fuelmuhafiz.test`; check the Boost `browser-logs` tool for console errors and use `get-absolute-url` for correct subdomain URLs.
7. **Gate** — `composer ci:check` (Pint, PHPStan level 7, `npm run check`, `tsc --noEmit`, full test suite) must pass. Run narrow filters (`php artisan test --compact --filter=CloseShift`) while iterating.
